# GCS Bucket 访问权限配置详解

## 📋 当前配置界面说明

这是 Bucket 创建时的访问权限配置步骤，需要正确配置才能让图片公开访问。

## ✅ 推荐的配置方式

### 方式 1：统一访问控制（推荐，更简单）

**配置步骤：**

1. **"禁止公开访问"部分：**
   - ✅ **不要勾选** "禁止公开访问此存储桶"
   - 保持未勾选状态

2. **"访问权限控制"部分：**
   - ✅ 选择 **"统一"** (Uniform)
   - 这是当前默认选中的选项，保持即可

3. **点击"继续"完成创建**

4. **创建后设置公开访问：**
   - 进入 Bucket → "权限" 标签
   - 点击 "授予访问权限"
   - 添加：
     ```
     新主体: allUsers
     角色: Storage Object Viewer
     ```
   - 保存

**优点：**
- 配置简单
- 所有对象使用相同的权限策略
- 更适合统一管理的场景

### 方式 2：精细控制（可选，更灵活）

如果你想要更灵活的对象级别控制：

1. **"禁止公开访问"部分：**
   - ✅ **不要勾选** "禁止公开访问此存储桶"

2. **"访问权限控制"部分：**
   - ✅ 选择 **"精细控制"** (Fine-grained control)
   - 允许为不同对象设置不同的权限

3. **点击"继续"完成创建**

4. **创建后设置公开访问：**
   - 可以通过 IAM 统一设置
   - 或通过 ACL 为单个对象设置

## 🔍 两个选项的区别

### 统一 (Uniform)
- 使用存储桶级别的 IAM 权限
- 所有对象继承相同的权限
- 90 天后会变成永久设置
- **适合我们的场景**：所有图片都需要公开访问

### 精细控制 (Fine-grained control)
- 支持对象级别的 ACL 权限
- 可以为不同对象设置不同权限
- 更灵活，但配置更复杂

## ⚠️ 重要提示

1. **不要勾选"禁止公开访问此存储桶"**
   - 如果勾选，即使设置了权限，图片也无法公开访问
   - 保持未勾选状态

2. **"统一"选项在 90 天后会变成永久设置**
   - 如果选择"统一"，90 天内可以改回"精细控制"
   - 90 天后无法更改
   - 对于我们的场景（所有图片都公开），"统一"是合适的

## 📝 推荐配置总结

对于我们的图片存储场景，推荐配置：

```
✅ 禁止公开访问此存储桶: 不勾选
✅ 访问权限控制: 统一 (Uniform)
```

然后创建后通过 IAM 添加 `allUsers: Storage Object Viewer` 权限即可。

## 🚀 下一步

配置完成后：
1. 点击"继续"完成 Bucket 创建
2. 在权限标签中设置公开访问（如方式 1 步骤 4）
3. 运行自动化迁移脚本：`./scripts/auto-migrate-to-gcs.sh`
