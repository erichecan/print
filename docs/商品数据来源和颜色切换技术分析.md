# 商品数据来源和颜色切换技术分析报告

**生成时间**: 2025-12-03 04:40:00

## 问题 1: 商品列表数据来源和差异分析

### 数据来源确认

**前端商品列表**:
- **API 端点**: `GET /api/products` (通过前端 Next.js API 路由代理)
- **后端控制器**: `backend/src/controllers/productController.js` → `getProducts()`
- **数据来源**: 从同一个 PostgreSQL 数据库读取
- **数据格式**: 针对前端展示优化

**后端管理端商品列表**:
- **API 端点**: `GET /api/admin/products`
- **后端控制器**: `backend/src/controllers/adminProductController.js` → `listProducts()`
- **数据来源**: 从同一个 PostgreSQL 数据库读取
- **数据格式**: 针对管理端展示，包含完整信息

### 数据差异原因

#### 1. 价格字段差异

**前端接口返回格式**:
```javascript
{
  price: {
    base: 24.99,    // basePrice / 100 (从分转换为元)
    sale: 19.99,    // salePrice (已经是元，不需要除以100)
    currency: 'CAD'
  }
}
```

**管理端接口返回格式**:
```javascript
{
  basePrice: 24.99,  // basePrice / 100 (从分转换为元)
  salePrice: 19.99   // salePrice (已经是元，不需要除以100)
}
```

**根本原因**:
- 数据库存储：
  - `basePrice`: `Int` 类型，存储为"分"（cents）
  - `salePrice`: `Decimal(10,2)` 类型，存储为"元"（金额，两位小数）
- 两个接口的数据格式化逻辑不同，但都从同一个数据库读取
- **已修复**: 统一了价格处理逻辑，确保两个接口返回的价格单位一致

#### 2. 颜色信息差异

**前端接口**:
```javascript
{
  variants: [
    { color: "Black", colorHex: "#000000" },
    { color: "Blue", colorHex: "#0066CC" }
  ]
}
```
- 只返回颜色名称和十六进制值
- 用于在商品卡片上显示颜色点

**管理端接口**:
```javascript
{
  variants: [
    {
      id: "...",
      color: "Black",
      colorHex: "#000000",
      size: "M",
      sku: "...",
      stockQuantity: 100,
      imageUrl: "...",
      // ... 完整字段
    }
  ]
}
```
- 返回完整的 variant 信息
- 包含库存、SKU、图片等所有字段

**原因**: 前端接口为了性能优化，只返回必要的颜色信息用于显示

#### 3. 图片信息差异

**前端接口**:
- 返回 `primaryImage`（主图）和 `images` 数组
- 用于商品列表展示

**管理端接口**:
- 返回完整的 `images` 数组
- 每个 `variant` 包含 `imageUrl`（该颜色变体的专属图片）

**原因**: 前端只需要主图，管理端需要完整信息用于编辑

### 解决方案

1. ✅ **统一价格格式**: 已修复价格处理逻辑，确保两个接口返回的价格单位一致
2. ✅ **数据验证**: 添加了兼容处理，支持历史数据
3. **建议**: 如果需要在前端显示更多颜色信息，可以修改前端接口返回完整的 variant 数据

## 问题 2: 颜色切换时图片变化机制

### 当前实现方式

**技术方案**: **预存多色图片**（方式 1）

系统使用数据库中每个 variant 的 `imageUrl` 字段来存储不同颜色的产品图片。

### 实现机制

1. **数据库设计**:
   - `Variant` 模型包含 `imageUrl` 字段
   - 每个颜色变体可以有自己的专属图片

2. **前端实现**:
   ```typescript
   // 获取当前显示的图片
   const currentImage = selectedVariant?.imageUrl 
     ? selectedVariant.imageUrl 
     : (product.images[selectedImageIndex]?.url || product.images[0]?.url || fallbackImage);
   ```

3. **颜色切换逻辑**:
   - 用户点击颜色按钮 → 更新 `selectedColor` 状态
   - 根据 `selectedColor` 查找对应的 `variant`
   - 如果 variant 有 `imageUrl`，使用它；否则使用产品主图

### 悬停预览功能

**新增功能** (2025-12-03 04:35:00):
- 鼠标悬停在颜色按钮上时，自动预览该颜色的图片
- 鼠标离开时，恢复显示选中颜色的图片
- 实现方式：使用 `onMouseEnter` 和 `onMouseLeave` 事件

```typescript
onMouseEnter={() => {
  if (isAvailable) {
    setHoveredColor(color.name);
  }
}}
onMouseLeave={() => {
  setHoveredColor(null);
}}
```

### 图片优先级

1. **悬停预览图片** (如果鼠标悬停在某个颜色上)
2. **选中 variant 的图片** (如果选择了颜色且有 variant.imageUrl)
3. **产品主图片** (product.images[0])
4. **默认图片** (fallbackImage)

### 技术细节

**不是图像处理技术**:
- ❌ 不是使用 Canvas 或图像处理库动态改变颜色
- ❌ 不是使用 CSS 滤镜改变图片颜色
- ✅ 是预先为每个颜色变体上传/存储了对应的产品图片

**优势**:
- 图片质量高，显示真实的产品颜色
- 性能好，不需要实时图像处理
- 用户体验好，切换流畅

**劣势**:
- 需要为每个颜色准备图片（存储空间）
- 需要在上传产品时管理多张图片
