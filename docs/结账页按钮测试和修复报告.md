## 问题分析

### 根本原因
当使用浏览器自动化工具（`browser_type`）填写表单字段时，可能无法正确触发 React 的 `onChange` 事件，导致：
1. 地址状态（`address`）没有更新
2. `addressReady` 计算仍基于空字段
3. Place Order 按钮保持禁用状态

### 代码检查
检查了 `apps/web/src/app/checkout/page.tsx` 的地址表单实现：
- ✅ `onChange` 处理器正确实现
- ✅ `addressReady` 计算逻辑正确
- ✅ 调试日志已添加

### 可能的原因
1. **浏览器工具限制**: `browser_type` 工具可能无法触发 React 的合成事件
2. **状态更新延迟**: 状态更新可能没有及时反映在日志中
3. **字段绑定问题**: 虽然代码看起来正确，但可能存在绑定问题

## 修复方案

### 方案 1: 改进地址状态更新验证
添加一个 `useEffect` 来监听地址状态变化，并输出更详细的日志：
```typescript
useEffect(() => {
  console.log('[Checkout Debug] Address state updated:', JSON.stringify(address, null, 2));
}, [address]);
```

### 方案 2: 手动触发 onChange 事件
在浏览器控制台中手动触发 `onChange` 事件，验证状态更新是否正常工作。

### 方案 3: 添加字段值验证日志
在每个字段的 `onChange` 处理器中添加日志，确认事件是否正确触发：
```typescript
onChange={(event) => {
  console.log('[Checkout Debug] Field changed:', fieldName, event.target.value);
  setAddress({ ...address, [fieldName]: event.target.value });
}}
```

### 方案 4: 使用 React DevTools
使用 React DevTools 检查组件状态，确认地址字段值是否已更新。
