# 购物车结账问题修复计划

## 问题分析

根据用户报告的错误和 Chrome DevTools 测试结果：

### 1. 后端 API 500 错误
- **`GET /api/promotions/product/:productId`** - 返回 500 错误
- **`POST /api/coupons/validate`** - 返回 500 错误

### 2. "Place Order" 按钮无法点击
- 用户填写完表单后，按钮仍然被禁用
- 按钮的禁用条件：`!stripe || isSubmitting || isFetchingRates || isCalculatingTotals || !cardComplete`

### 3. 其他错误（次要）
- `/chat` 路由 404（Next.js 预取，不影响功能）
- `/sitemap.xml` 路由 404（Next.js 预取，不影响功能）

## 修复步骤

### 阶段 1：修复后端 API 500 错误

#### 1.1 修复 promotions API
- **文件**：`backend/src/controllers/promotionController.js`
- **问题**：`getPromotionsForProduct` 可能因为数据库查询失败而返回 500
- **修复**：
  - 添加详细的错误日志
  - 处理产品不存在的情况
  - 确保 `mapPromotion` 函数正确处理所有字段

#### 1.2 修复 coupons validate API
- **文件**：`backend/src/controllers/couponController.js`
- **问题**：`validateCoupon` 可能因为数据库查询失败而返回 500
- **修复**：
  - 添加详细的错误日志
  - 改进错误处理
  - 确保 Prisma 查询正确

### 阶段 2：修复 "Place Order" 按钮问题

#### 2.1 调试按钮禁用状态
- **文件**：`apps/web/src/app/checkout/page.tsx`
- **问题**：按钮可能因为 `cardComplete` 状态未正确设置而被禁用
- **修复**：
  - 添加调试日志，跟踪按钮禁用原因
  - 确保 Stripe CardElement 正确初始化
  - 检查 `cardComplete` 状态更新逻辑

#### 2.2 改进表单验证
- 确保所有必填字段都有明确的验证反馈
- 添加表单验证错误提示

### 阶段 3：错误抑制（可选）

对于不影响功能的 404 错误（`/chat`, `/sitemap.xml`），可以通过以下方式处理：
- 在 `GlobalErrorFilter` 中添加这些路由的错误过滤
- 或者创建这些路由的空实现
