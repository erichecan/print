Section 01
系统架构概览
🎯 核心玩法

老用户分享专属邀请链接，好友通过链接完成首单付款后，老用户自动获得阶梯返现奖励。

每个用户最多邀请 3 位好友，累计最高返现 CA$1400。

🏗 技术架构

前端：Next.js 落地页、分享页、用户钱包页面（路径 /referral/*）

后端：Express.js API（/api/referral/* 和 /api/admin/referral/*）

数据库：PostgreSQL，Prisma ORM 管理 3 张裂变专属表

📊 数据模型说明
数据表 用途 关键字段
referral_campaigns 活动配置（全局唯一） isActive、cap（上限）、tier1/2/3Amount（各档返现金额）
referral_user_codes 用户专属邀请码 userId、code（格式 PNG+哈希，如 PNG7A3F2B）
referral_links 每笔推荐记录 promoterUserId、referredUserId、orderId、tier、rewardAmount、rewardStatus
🔗 关键页面路由
路径受众说明
/referral所有人活动介绍落地页，可带 ?ref=CODE 参数
/referral/invite?ref=CODE被邀请人好友收到链接后的落地页
/referral/me / /referral/dashboard推广者（登录）查看邀请进度、钱包余额
/referral/share推广者（登录）获取专属链接、一键分享
/referral/wallet推广者（登录）返现明细流水
/admin/referral-settings管理员配置活动参数
ℹ️ 系统防护机制
  • 禁止自买：推广者和被邀请人为同一账号时，系统自动拒绝记录
  • 一次生效：同一被邀请人只计入一次推荐（已参与过的不重复计算）
  • 上限保护：超出 cap（默认 3）后的订单不再触发奖励
  • 幂等保护：同一 orderId 不会被重复处理

Section 02
后台配置手册
⚠️ 配置生效范围
后台修改「活动配置」后立即全局生效，无需重启服务。建议在正式上线前 30 分钟内完成最终配置，避免用户在过渡期看到不一致数据。
⚙️ 第一步：进入管理后台活动配置
# 生产环境管理后台
https://printngoplus.com/admin/referral-settings

# 本地开发环境
http://localhost:3000/admin/referral-settings

需要管理员账号登录。配置页面对应后端 API：PUT /api/admin/referral/campaign

🎛 可配置参数说明
参数名含义默认值建议范围
isActive 活动开关（关闭后所有新推荐均不生效） true（开启） 上线时设为 true；节假日关闭时设为 false
cap 每位推广者最多可获奖励的邀请人数 3 3–5，超出后系统不再记录新奖励
tier1Amount 邀请第 1 位好友的返现金额（CA$） 200 150–300，设为订单均价的 15–25%
tier2Amount 邀请第 2 位好友的返现金额（CA$） 400 应大于 tier1，建议 2× tier1
tier3Amount 邀请第 3 位好友的返现金额（CA$） 800 应大于 tier2，建议 4× tier1
💡 返现比例设计原则

以下为默认配置（CA$200 / CA$400 / CA$800）的成本分析，供参考：

档次返现假设客单价推广成本率备注
第 1 单 CA$200 CA$1000+ ≈20% 低于传统广告 CAC，合理
第 2 单 CA$400 CA$1000+ ≈40% 第 2 单毛利覆盖返现即可
第 3 单 CA$800 CA$1000+ ≈80% 第 3 单引流价值 > 利润

三挡设计逻辑：越往后越难完成，奖励越高，刺激推广者持续拉新。

Section 03
活动上线清单
✅ 执行原则
按顺序勾选，全部通过后才发布推广物料。跳过任何一项都可能导致用户进入流程后无法完单或返现计算错误。
📋 D-3（上线前 3 天）
  • 确认返现金额和档次，在管理后台保存配置
  • 确认 isActive = true，活动开关已开启
  • 确认 cap = 3（或你想要的上限数字）
  • 准备至少一个测试账号，验证邀请码生成（访问 /referral/me）
  • 确认支付流程正常（用测试账号完成一笔订单）
  • 确认推广者钱包页面正确显示 PENDING 奖励
📋 D-1（上线前 1 天）
  • 准备推广物料：朋友圈海报、微信消息模板、群发话术（见 Section 04）
  • 向现有用户发送活动预热通知（邮件/微信）
  • 客服同学阅读 Section 06 客服话术，准备回复模板
  • 配置好返现核销流程，明确打款负责人
  • 生产环境二次验证：用真实账号从 /referral/invite?ref=CODE 走完整个流程
📋 D-day（上线当天）
  • 09:00 — 发布朋友圈/公众号推文
  • 09:30 — 在老用户群发送活动通知
  • 10:00 — 检查管理后台 stats（第一批邀请链接是否生成）
  • 全天 — 监控 Cloud Run 日志，确认 [Referral] Reward created 正常出现
  • 18:00 — 汇总当日数据：新增推荐数、新增订单数、待付返现总额
🚨 上线后 30 分钟内必测
用一个全新账号（从未下过单）通过邀请链接下单，确认：
① 推广者后台显示「第 1 单 PENDING CA$200」
② 被邀请人下单成功，无报错
③ 后台 GET /api/admin/referral/stats 返回 totalReferrals = 1

Section 05
裂变全流程详解
📌 推广者视角（老用户）
1
获取专属邀请码
推广者访问 /referral/me 或 /referral/share，系统自动为账号生成唯一邀请码（格式：PNG + 6 位字母数字，如 PNG7A3F2B）。码一旦生成永不变化。
2
分享邀请链接
点击「邀请好友」按钮，复制链接：
https://printngoplus.com/referral/invite?ref=PNG7A3F2B
可发送给微信好友、群、朋友圈等任意渠道。
3
等待好友下单
好友打开链接、登录账号（或注册新账号）、完成下单并支付。推广者无需做任何额外操作。
4
奖励进入钱包（PENDING 状态）
好友支付成功后，系统自动在钱包记录一笔 PENDING 奖励（第 1 单 CA$200）。推广者可在 /referral/wallet 查看。
5
运营人工审核后打款
运营人员在后台确认订单无异常后，将状态标记为 PAID，通过微信/支付宝等渠道将返现打给推广者。打款时间：7–14 个工作日内。
📌 被邀请人视角（新客户）
1
打开邀请链接
点开好友发来的链接，进入 /referral/invite?ref=CODE 页面，浏览器将邀请码临时存入 sessionStorage。
2
登录或注册账号
未登录用户被引导至登录页，登录后自动跳回带邀请码的结账页。邀请码在整个会话中保持有效。
3
选择商品、完成支付
正常浏览商品目录、加入购物车、完成支付。系统在支付成功时自动将邀请码关联到该订单。
4
自动获得推广资格
完成首单后，被邀请人自动获得自己的邀请码，可进入 /referral/me 开始邀请自己的好友，实现裂变扩散。

⚠️ 系统会拒绝的情况

Section 06
客服话术 & 问题处理
ℹ️ 客服处理原则
先安抚用户情绪，再查后台数据，再解释规则。绝不承诺「系统没有的功能」（如手动补录超上限奖励）。所有例外情况须升级给运营主管决策。
Q1 我邀请了好友，为什么返现没到账？
您好！返现需要在好友完成支付后 7–14 个工作日内到账，这段时间我们会人工核实订单状态。

您可以先在「我的推广中心」→「钱包」查看是否显示 PENDING（待审核）状态——如果显示了，说明系统已经记录，等待我们核实后打款即可。

如果好友确实已付款但钱包里没有任何记录，请告诉我好友的订单号，我帮您核查一下。
Q2 我买了好几次，为什么推广者只记了一单？
活动规则是：同一位被邀请人只有第一笔订单计入推荐，后续复购不重复计算。这是为了保证活动的公平性，在活动说明页面有说明。

如果您还有其他朋友尚未下过 PrintNGo 的单，邀请他们也可以继续累积返现哦！
Q3 好友通过我的链接下单了，但系统显示"不符合条件"
可能有以下几种情况，我帮您逐一排查：

1. 好友之前已经用过别人的邀请链接 —— 每位用户只能被邀请一次，已使用过则不再计入
2. 好友的订单金额未达到门槛 —— 请确认订单已成功付款
3. 您自己的邀请上限已满（最多 3 位）—— 请登录查看当前推荐进度

请提供好友的订单号，我来具体核查是哪种情况。
Q4 返现什么时候打过来？用什么方式？
好友支付成功后，我们会在 7–14 个工作日内通过微信转账 / 支付宝将返现打给您（具体方式届时我们会主动联系您确认收款账号）。

如果超过 14 个工作日仍未收到，请直接联系我们，我们第一时间处理！
Q5 我能不能一次性邀请很多人，超过 3 个？
活动规则每个账号最多获得 3 单返现奖励（共 CA$1400），超出 3 位好友的下单不会再产生奖励记录。

当然您可以继续推荐更多朋友使用 PrintNGo，虽然超出部分无返现，但感谢您的支持！如果后续我们调整了上限，会在官方渠道第一时间通知。
Q6 链接打开了但好友说看不到优惠/下单入口在哪？
邀请链接打开后会进入邀请落地页，好友点击「立即下单」按钮，跳转到商品目录即可正常选购。如果是第一次用，需要先注册或登录，注册后会自动回到下单流程。

如果页面加载有问题，可以尝试：换一个浏览器打开、或者复制链接到 Chrome/Safari 重新打开。
🚨 需要升级处理的情形
情形判断标准升级对象
用户声称有系统 bug 导致奖励未记录 后台 logs 无 [Referral] Reward created 记录，且订单存在 技术负责人排查 referralService 日志
用户要求补发超上限奖励 推荐数已 ≥ cap，用户情绪激动 运营主管决策是否例外处理
疑似批量刷单（同一 IP 大量新账号） 短时间内 referral_links 大量增加，但订单地址/IP 相同 运营主管 + 技术，暂停异常推广者奖励
用户要求退款但推广者已获奖励 被邀请人申请退款后，对应的 referral_link 应标记 CANCELLED 技术手动更新 rewardStatus = CANCELLED

Section 07
返现核销操作流程
⚠️ 操作权限
核销打款操作（markRewardPaid）需要管理员权限，普通客服账号无权限执行。所有打款操作须由运营主管或财务负责人执行，并保留打款凭证。
📋 核销流程（每周定期执行）
1
拉取 PENDING 奖励列表
访问管理后台或调用 API 获取所有待核销记录：
curl -H "Authorization: Bearer ADMIN_TOKEN" \
"https://printngoplus.com/api/admin/referral/links?status=PENDING&limit=50"
返回字段包括：推广者 userId、被邀请人 userId、orderId、tier、rewardAmount、createdAt
2
逐一核验订单状态
检查每条记录对应的 orderId 是否已完成（未退款）。可通过管理后台 /admin/online-orders 查询订单状态。
如订单已退款：在数据库将对应 referralLink 的 rewardStatus 改为 CANCELLED，不予打款。
3
联系推广者确认收款账号
通过推广者账号邮箱或预留手机号，联系确认打款方式（微信/支付宝）和账号。
建议用统一格式记录：推广者ID | 金额 | 微信/支付宝 | 账号 | 核实日期
4
完成打款
通过微信/支付宝完成转账，备注「PrintNGo 推荐返现 #ORDERID」，保留截图。
5
在后台标记为 PAID
打款成功后，调用 API 将记录标为已付款：
curl -X PUT \
  -H "Authorization: Bearer ADMIN_TOKEN" \
  "https://printngoplus.com/api/admin/referral/rewards/LINK_ID/paid"
此操作会自动记录 paidAt 时间戳，推广者钱包状态同步更新为 PAID。
📊 奖励状态说明
状态含义推广者看到什么运营操作
PENDING 好友已付款，等待运营核实打款 「待到账 CA$XXX」 核实订单后打款，改为 PAID
PAID 返现已打款给推广者 「已到账 CA$XXX」 无需操作
CANCELLED 订单退款或违规，返现取消 「已取消」 无需打款，可向用户说明原因
📅 建议打款周期
🗓 每周一固定批量处理

每周一上午拉取上周产生的 PENDING 记录，统一联系、统一打款，提高效率，避免漏单。

⏱ 最长等待承诺：14 个工作日

对外承诺 7–14 个工作日到账，内部目标是 7 个工作日内处理完毕，预留缓冲时间应对用户询问。

🚨 严禁操作
  • 不得在订单退款期间（通常下单后 7 天内）提前打款，防止退款后返现无法追回
  • 不得手动跳过 API 直接修改数据库状态（会导致 paidAt 时间戳丢失）
  • 不得在未核实推广者身份（账号真实、未违规）的情况下打款

🔍 需要排查的异常信号
异常现象可能原因排查步骤
推荐数突然停止增长 活动被关闭 / onOrderPaid 未调用 / 结账流程 bug 检查 isActive；查 Cloud Run 日志是否有 [Referral] Reward created
PENDING 数量异常飙升 疑似刷单；或上周核销积压 对比 IP / 设备，判断是否有异常账号集中下单
用户反馈奖励未记录 代码 bug / 邀请码未正确传递 在 referral_links 查 orderId；查 logger 日志
某推广者奖励档次错误 tier 计算 bug / 手动操作导致数据不一致 查该用户所有 referral_links 记录，核对 completedCount 逻辑
📉 活动效果评估指标
指标计算方式健康范围参考
邀请转化率 完成下单的被邀请人数 ÷ 点击邀请链接人数 ≥ 15%（低于 10% 需优化落地页）
活跃推广者比例 产生 ≥1 条 referral_link 的用户 ÷ 总注册用户 ≥ 5%（低于 2% 说明种子用户激活不足）
平均档次完成数 referral_links 总数 ÷ 参与推广者数 目标 > 1.5（说明推广者持续推荐而非仅推一次）
推广成本率 已打款 paidAmount ÷ 对应订单总 GMV ≤ 25%（控制在合理 CAC 范围）

🗂 数据库快速查询（Prisma Studio 或 SQL）
-- 查看所有待核销奖励（按时间降序）
SELECT rl.id, rl.promoter_user_id, rl.referred_user_id,
       rl.order_id, rl.tier, rl.reward_amount, rl.created_at
FROM referral_links rl
WHERE rl.reward_status = 'PENDING'
ORDER BY rl.created_at DESC;

-- 统计某推广者的总返现
SELECT SUM(reward_amount) FROM referral_links
WHERE promoter_user_id = 'USER_ID' AND reward_status != 'CANCELLED';

-- 查看某用户的邀请码
SELECT code FROM referral_user_codes WHERE user_id = 'USER_ID';
