# 后端登录问题修复说明

## 问题描述

用户反馈："后端服务有不能登录了呢"，前端登录时出现 401 Unauthorized 错误。

## 问题分析

1. **后端 API 本身正常工作**：通过 `curl` 直接测试后端登录 API 返回 200 状态码，说明后端服务功能正常。
2. **跨域 Cookie 问题**：前端直接调用后端 API（跨域），Cookie 可能无法正确传递和保存，特别是在 GCP Cloud Run 环境下。
3. **数据库账户确认**：管理员账户 `admin@souvenirplus.com` / `admin123` 存在于数据库中。

## 修复方案

### 1. 创建 Next.js API 路由代理

创建了同域的 API 路由来代理登录相关请求：

- `apps/web/src/app/api/auth/login/route.ts` - 代理 POST `/api/auth/login`
- `apps/web/src/app/api/auth/me/route.ts` - 代理 GET `/api/auth/me`

这些路由：
- 接收前端的登录请求（同域，无跨域问题）
- 转发请求到后端服务
- 正确传递和转发 Cookie（包括 `Set-Cookie` 头）

### 2. 修改前端 API 调用

修改了 `apps/web/src/lib/api.ts` 中的 `authApi`：

- `authApi.login` - 现在使用 `/api/auth/login`（同域路由）
- `authApi.me` - 现在使用 `/api/auth/me`（同域路由）

其他认证相关的 API（如 `logout`, `updateProfile`）仍然直接调用后端。

### 3. Cookie 传递机制

- 前端 → Next.js API 路由：Cookie 自动传递（同域）
- Next.js API 路由 → 后端：手动传递 Cookie 头
- 后端 → Next.js API 路由：转发 `Set-Cookie` 头
- Next.js API 路由 → 前端：浏览器自动保存 Cookie（同域）

## 技术细节

### Next.js API 路由配置

```typescript
// 获取后端 API URL
function getBackendApiBase(): string {
  if (process.env.NEXT_PUBLIC_API_URL) {
    return process.env.NEXT_PUBLIC_API_URL.replace(/\/$/, '');
  }
  return 'http://localhost:3001/api'; // 开发环境默认
}
```

### Cookie 头处理

Next.js API 路由需要正确处理多个 `Set-Cookie` 头：

```typescript
const setCookieHeaders = upstream.headers.getSetCookie?.() || [];
if (setCookieHeaders.length > 0) {
  setCookieHeaders.forEach(cookie => {
    responseHeaders.append('set-cookie', cookie);
  });
}
```

## 注意事项

1. **环境变量**：确保 `NEXT_PUBLIC_API_URL` 环境变量在生产环境中正确设置为后端服务的 URL（例如：`https://print-main-backend-xxx.run.app/api`）。

2. **Cookie 设置**：后端服务需要正确设置 Cookie 属性（`sameSite: 'none'`, `secure: true`）以支持跨域请求，但现在通过 Next.js API 路由代理，已经是同域请求，所以 Cookie 设置应该更加简单。

3. **其他认证 API**：目前只有 `login` 和 `me` 使用代理路由。如果需要，可以扩展其他认证相关的 API（如 `logout`）。
