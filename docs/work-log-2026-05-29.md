# 工作进度报告 — 2026-05-29

## 今日完成事项

### 1. 修复「在设计器中打开」链接缺失 designId

**问题**：Admin 后台订单详情页的「在设计器中打开」按钮，链接中没有带 `designId` 参数，导致设计器打开后使用默认产品、设计稿无法加载。

**修复**：从订单 `items` 中找到第一个含 `designId` 的商品，将 `&designId=xxx` 拼入跳转链接。

**影响文件**：`apps/web/src/app/admin/online-orders/[id]/AdminOrderDetailClient.tsx`

---

### 2. 修复客户订单详情页图片重叠显示

**问题**：商品缩略图使用了 `position: absolute` 将设计图叠在产品图上，导致两张图片在视觉上互相遮挡、显示混乱。

**修复**：改为只显示一张图——优先用 `designThumbnailUrl`，没有则退回 `thumbnail`，去除双层叠加结构。

**影响文件**：`apps/web/src/app/orders/[orderNumber]/OrderDetailContent.tsx`

---

### 3. 定位「无印刷位置信息」根本原因

**现象**：印刷排版页（gang sheet）显示"无印刷位置信息（设计审核同步时未导出图稿）"。

**根因分析**：链接中缺少 `designId`（即第 1 项的 bug），导致设计器打开时画布为空，同步时没有任何图层可导出，因此 `printSpecs.positions` 为空数组。

**处理方式**：第 1 项 bug 修复后，新订单走正确流程可正常导出。历史订单需管理员重新打开设计器（链接已修复）后点击「同步设计」重新导出。

---

### 4. 实现多视图持久化（全视图还原到 store）

**背景**：原设计数据库只存储一个视图（front）的 canvas 快照，加载设计时只能还原 front 视图，导致切换到其他视图（back、left-sleeve 等）时内容丢失，同步按钮也只能导出正面图稿。

**实现方案**：

| 层级 | 改动内容 |
|------|---------|
| 数据库 | `designs` 表新增 `views_data JSONB` 列，直接执行 SQL + 创建迁移文件并标记为已应用 |
| Prisma Schema | `Design` 模型新增 `viewsData Json? @map("views_data")` 字段，重新生成客户端 |
| 后端 Controller | `createDesignDraft` / `updateDesignDraft` 接收并存储 `viewsData`；`getDesignDraft` 返回时自动包含该字段 |
| 前端 API 类型 | `DesignDraft`、`CreateDesignPayload`、`UpdateDesignPayload` 均新增 `viewsData` 字段 |
| 前端保存逻辑 | `useDesign.ts` 在保存时从 Zustand store 读取所有含图层的视图，序列化为 `viewsData` 随请求一起发送 |
| 前端加载逻辑 | `handleLoadDesign` 加载完成后，遍历 `loadedDesign.viewsData`，对每个视图调用 `setViewLayers(viewId, layers)`，全量还原到 store |

**影响文件**：
- `prisma/schema.prisma`
- `prisma/migrations/20260529000000_add_design_views_data/`
- `backend/src/controllers/designController.js`
- `apps/web/src/app/design-lab/api/design.ts`
- `apps/web/src/app/design-lab/modules/save/useDesign.ts`
- `apps/web/src/app/design-lab/DesignLabClient5.0.tsx`
