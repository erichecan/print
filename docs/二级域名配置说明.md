# 二级域名配置说明

## 🤔 你的问题解答

**问题：如果我设置了前端服务的二级域名，还需要设置后端服务的二级域名吗？**

### 简单回答：

**不一定需要，但强烈推荐设置！**

---

## 📊 两种方案对比

### 方案 1：只配置前端二级域名

**配置内容：**
- ✅ `app.souvenirplusinc.com` → 前端服务（用户访问的网站）
- ❌ 后端继续使用 Cloud Run 原始 URL

**访问地址：**
- 前端：`https://app.souvenirplusinc.com` ✅ 友好
- 后端：`https://print-main-backend-234065158862.us-central1.run.app/api` ❌ 难记

**工作原理：**
- 前端网站运行在 `app.souvenirplusinc.com`
- 前端通过环境变量 `NEXT_PUBLIC_API_URL` 知道后端地址
- 这个地址存储在 GCP Secret Manager 中，目前是：`https://print-main-backend-234065158862.us-central1.run.app/api`
- 前端会使用这个地址调用后端 API

**优点：**
- ✅ 只需配置一个 DNS 记录
- ✅ 用户访问网站使用友好域名
- ✅ 配置简单

**缺点：**
- ❌ 后端 API 地址仍然是难记的 URL
- ❌ 如果 Cloud Run URL 改变，需要更新 Secret Manager
- ❌ 不够专业

---

### 方案 2：同时配置前后端二级域名（推荐）

**配置内容：**
- ✅ `app.souvenirplusinc.com` → 前端服务
- ✅ `api.souvenirplusinc.com` → 后端服务

**访问地址：**
- 前端：`https://app.souvenirplusinc.com` ✅ 友好
- 后端：`https://api.souvenirplusinc.com/api` ✅ 友好且专业

**工作原理：**
- 前端网站运行在 `app.souvenirplusinc.com`
- 后端 API 运行在 `api.souvenirplusinc.com`
- 前端通过环境变量知道后端地址是 `https://api.souvenirplusinc.com/api`
- 需要更新 Secret Manager 中的 API URL

**优点：**
- ✅ 两个地址都很友好、专业
- ✅ 即使 Cloud Run URL 变化，二级域名不变
- ✅ 符合最佳实践
- ✅ 更容易维护

**缺点：**
- ❌ 需要配置两个 DNS 记录
- ❌ 需要在 GCP 创建两个域名映射

---

## 🎯 推荐：方案 2

虽然需要多配置一个后端域名，但这是**最佳实践**，原因：

1. **更专业**: 标准的做法是前端和 API 分开
2. **更稳定**: 即使 Cloud Run 服务 URL 改变，你的二级域名不变
3. **更易维护**: API 地址清晰明确
4. **SSL 免费**: Cloud Run 自动为两个域名提供免费 SSL 证书

## ✅ 建议配置步骤

### 1. 在 GCP 创建域名映射

#### 创建前端域名映射：
```bash
gcloud beta run domain-mappings create \
  --service=print-main-frontend \
  --domain=app.souvenirplusinc.com \
  --region=us-central1 \
  --project=moonlit-gamma-479502-r6
```

#### 创建后端域名映射：
```bash
gcloud beta run domain-mappings create \
  --service=print-main-backend \
  --domain=api.souvenirplusinc.com \
  --region=us-central1 \
  --project=moonlit-gamma-479502-r6
```

**执行后会显示需要添加的 DNS 记录，类似：**
```
Type: CNAME
Name: app
Value: ghs.googlehosted.com.
```

---

### 2. 在 cPanel Zone Editor 中添加 DNS 记录

根据你提供的截图，操作步骤：

#### 添加前端 DNS 记录：
1. 点击 **"+ CNAME Record"** 按钮
2. 填写：
   - **Name**: `app` （只写前缀）
   - **Value**: `ghs.googlehosted.com.` （末尾有点）
   - **TTL**: `3600`

#### 添加后端 DNS 记录：
1. 再次点击 **"+ CNAME Record"** 按钮
2. 填写：
   - **Name**: `api` （只写前缀）
   - **Value**: `ghs.googlehosted.com.` （末尾有点）
   - **TTL**: `3600`

---

### 3. 等待 DNS 传播（5-30 分钟）

验证 DNS 记录：
```bash
dig app.souvenirplusinc.com CNAME
dig api.souvenirplusinc.com CNAME
```

---

### 4. 更新后端 API URL

DNS 生效后，更新 Secret Manager：
```bash
echo -n "https://api.souvenirplusinc.com/api" | \
  gcloud secrets versions add api-url \
  --data-file=- \
  --project=moonlit-gamma-479502-r6
```

---

### 5. 重新部署前端（使用新的 API URL）

需要重新部署前端以使用新的 API URL。

## 💡 总结

**回答你的问题：**

1. **后端访问链接是什么？**
   - 当前：`https://print-main-backend-234065158862.us-central1.run.app/api`
   - 配置后：`https://api.souvenirplusinc.com/api`

2. **需要配置后端二级域名吗？**
   - **不是必须的**，但**强烈推荐**
   - 如果不配置，后端仍然可以通过原始 Cloud Run URL 工作
   - 配置后更专业、更稳定、更易维护

**建议：虽然多一个步骤，但配置后端二级域名是最佳实践！**
