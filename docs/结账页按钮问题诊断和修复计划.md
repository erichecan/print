## 按钮禁用条件分析

### Place Order 按钮

```typescript
disabled={!stripe || isSubmitting || isFetchingRates || isCalculatingTotals || !cardComplete}
```

**可能的原因**：
1. **!stripe** - Stripe 未加载（最可能）
   - Stripe publishable key 配置问题
   - Stripe 脚本加载失败
   - Stripe 初始化延迟

2. **!cardComplete** - 卡片信息未填写完整
   - Stripe CardElement 的 onChange 事件未正确触发
   - 卡片信息填写后状态未更新

3. **isFetchingRates** - 正在获取运费（不太可能）
4. **isCalculatingTotals** - 正在计算总计（不太可能）
5. **isSubmitting** - 正在提交订单（不太可能）

### Apply Coupon 按钮

```typescript
disabled={applyingCoupon || !couponCode.trim() || !addressReady}
```

**可能的原因**：
1. **!addressReady** - 地址信息未填写完整（最可能）
   - 某个必填字段未填写
   - 地址字段验证逻辑问题

2. **!couponCode.trim()** - 未输入优惠券代码（正常）
3. **applyingCoupon** - 正在应用优惠券（不太可能）

## 预期修复方案

### 方案 1：Stripe 未加载

**症状**：日志显示 `disabledReason: "no-stripe"`

**修复**：
1. 检查 `NEXT_PUBLIC_STRIPE_PUBLISHABLE_KEY` 环境变量是否配置
2. 检查 Stripe 脚本是否正确加载
3. 添加 Stripe 加载失败的错误处理

### 方案 2：卡片信息未完整

**症状**：日志显示 `disabledReason: "card-incomplete"`，但用户已填写卡片信息

**修复**：
1. 检查 Stripe CardElement 的 onChange 事件是否正常触发
2. 确保 `cardComplete` 状态正确更新
3. 添加卡片输入验证逻辑

### 方案 3：地址信息未完整

**症状**：Apply 按钮显示 `disabledReason: "address-not-ready"`，但用户已填写地址

**修复**：
1. 检查地址字段验证逻辑
2. 确保所有必填字段都被正确检查
3. 修复 `addressReady` 计算逻辑
