1. 项目目标

PrintNGo 需要一个本地 Python 工具，把供应商产品页转成可审核、可重生、可导出的原创电商服装图片。 系统不直接复制供应商图片，而是从供应商页面和图片中提取商品属性，再生成新的图片表达。

第一阶段只做最小可用链路： 输入一个供应商 URL，保存原图和产品信息，生成一张原创图，生成本地审核 HTML，并支持按产品 ID 重新生成。

项目默认运行在本机，不直接上传到生产网站。所有原图、生成图、审核状态先保存在本地文件夹和 SQLite 数据库中。

2. 核心流程

1 批量抓取 从一个 URL 或 urls.txt 读取供应商产品页。
2 特征提取 提取产品名、品牌、款式、颜色、面料、版型和主图。
3 原创生成 用商品特征生成新的电商服装图。
4 人工审核 在本地 HTML 或网页中对比原图和生成图。
5 单张重生 按产品 ID 带备注重新生成，不影响其他产品。 
供应商 URL
  -> scrape.py 抓取页面和图片
  -> products.db 保存元数据
  -> generate.py 生成原创图
  -> make_review_html.py 生成审核页
  -> regenerate.py 按 ID 重生
  -> export_approved.py 导出通过图片和 CSV

5. 功能模块

URL 导入与抓取

  • 支持命令行输入单个 URL。
  • 后续支持 urls.txt 批量导入。
  • 优先用 Playwright 处理 JS 动态页面。
  • 抓取标题、主图、描述、颜色、品牌和款号。
  • 把主图保存到 data/originals/。

图片特征提取

  • 识别服装类型、领口、袖长、下摆、肩线和版型。
  • 识别颜色、面料观感、褶皱和穿着效果。
  • 把结果保存为结构化 JSON，供生成 prompt 使用。

原创图片生成

  • 根据商品特征生成新的电商图。
  • 保留商品属性，不保留原图摄影表达。
  • 保存生成图到 data/generated/。
  • 记录 prompt、时间、状态和错误信息。

审核与重生

  • 审核页展示原图和生成图对比。
  • 可通过、拒绝、备注和重新生成。
  • 重生只处理指定产品 ID。
  • 审核通过后导出到 data/approved/。

6. 图片生成原则

生成图的核心原则是：保留商品，不保留供应商图片的版权表达。

允许保留

  • 衣服类型，例如短袖 T 恤、Polo、帽衫、背心。
  • 领口形状、袖长、肩线、下摆、版型松紧。
  • 颜色、面料质感、自然褶皱、穿着效果。
  • 商品规格中的品牌、款号和材质信息，前提是商品本身允许销售和展示。

必须改变

  • 模特身份、脸、发型和明显个人特征。
  • 完全相同的姿势、构图、裁切、灯光和背景。
  • 供应商水印、页面文字、摄影棚风格和图片后期效果。

基础 prompt 模板

Create an original high-resolution e-commerce apparel photo of [garment type]
worn by a new model. Preserve the garment attributes: [fit], [neckline],
[sleeve length], [hem], [color], [fabric texture], and realistic fabric folds.
Use a different model, different pose, different lighting setup, and different
composition from the supplier reference. Use a clean white or light gray studio
background, realistic proportions, no text overlays, no watermarks, and no extra logos.
Do not copy the exact model, face, pose, lighting, background, crop, or composition
from the supplier image.

备注重生模板

Previous generation issue: [review note].
Regenerate the product image while correcting that issue.
Keep the same product color, garment type, fit, neckline, sleeve length,
fabric texture, and e-commerce product-photo quality.

8. 执行阶段

阶段 1：本地最小可用版本

  • 创建 Python 项目结构、依赖文件和数据库初始化。
  • 实现单 URL 抓取和图片下载。
  • 实现单 ID 图片生成。
  • 生成本地审核 HTML。
  • 实现单 ID 备注重生。
python app/scrape.py "https://supplier.com/product/xxx"
python app/generate.py --id 1
python app/make_review_html.py
python app/regenerate.py --id 1 --note "领口不够圆，袖子太长"
python app/export_approved.py

阶段 2：批量 URL

  • 支持 urls.txt 每行一个产品页。
  • 增加失败重试和错误记录。
  • 支持只生成 pending_generation 状态的产品。

阶段 3：网页审核

  • 用 FastAPI 和 Jinja2 做本地审核页面。
  • 按钮直接调用通过、拒绝和重生接口。
  • 支持备注输入和大图预览。

阶段 4：质量评分

  • 自动检查颜色、领口、袖长、版型和多余 logo。
  • 保存 quality_score 和质量备注。
  • 低分图片自动进入待重生状态。

阶段 5：导出和对接

  • 通过图片复制到 data/approved/。
  • 导出 CSV：产品名、款号、颜色、图片路径。
  • 后续可对接商品后台或电商平台。

9. 合规与风险

禁止目标： 这个工具不能用来一比一仿制供应商图片、复刻模特、复刻摄影构图，或移除水印后当作自有图片使用。
  • 供应商网站条款需要单独确认，尤其是自动抓取、图片下载和内部参考使用。
  • 原图只作为商品属性参考，不作为最终商业图片直接发布。
  • 生成 prompt 默认加入“不复制原模特、姿势、灯光、背景、构图”的限制。
  • 如果供应商图片带商标、印花或版权图案，需要人工确认是否有销售授权。
  • 正式实现前，需要再次核对当前 OpenAI 图片生成、编辑和视觉理解 API 的最新参数、模型名称和限制。
建议保留审核记录： 保存原图路径、生成 prompt、生成时间、审核备注和通过人，方便后续追溯每张图的来源和修改原因。

10. 第一版验收标准

  1. 输入一个供应商 URL 后，系统能保存产品名、原图 URL、本地原图路径和基础描述。
  2. 系统能为指定产品 ID 生成一张原创电商服装图，并保存到 data/generated/。
  3. 审核 HTML 能展示产品编号、产品名、原图、生成图、状态、prompt 和备注。
  4. 系统能按产品 ID 带备注重新生成一张图片，不影响其他产品。
  5. 审核通过的图片可以导出到 data/approved/，并生成 CSV。
