第一步：抓取竞品参考图

读取 customink_urls.csv 或通过 --url 传入单个 URL，为每种颜色下载正面参考图，结果写入 SQLite 数据库 products.db。

命令

# 单个 URL
python app/batch_customink.py --url https://www.customink.com/products/bags/tote-bags/...

# 批量读取 customink_urls.csv
python app/batch_customink.py

# 强制重新下载已存在的图片
python app/batch_customink.py --force

# 使用自定义 CSV 文件
python app/batch_customink.py --csv my_urls.csv

颜色发现策略

主路线：MMS Styles API

优先调用 CustomInk 内部 API，一次性获取该产品所有颜色及其 colorId：

GET https://www.customink.com/mms/api/out/v2/styles.json?ids={product_id}

返回 JSON 中的 colors / color_groups 数组，每项包含 id（colorId）和 name。

Fallback：Playwright 页面扫描

若 MMS API 失败（返回空或报错），自动启动无头 Chromium：

  • 拦截 CDN 图片请求，从 URL 提取 colorId
  • 拦截页面内的 styles.json / colors.json API 响应
  • 从 DOM color swatch 元素读取 data-color-id + 颜色名称
  • 三路结果合并，以 MMS API 数据优先

CDN 图片下载

# 每种颜色的正面参考图 URL 格式
https://mms-images-prod.imgix.net/mms/images/catalog/colors/{color_id}/views/alt/front_large_extended.png

# 本地保存路径
shopify/data/originals/customink_{product_id}_{color_id}_front.png

SQLite 状态写入

字段说明示例
supplier_url去掉查询参数的 URL（唯一键之一）https://www.customink.com/.../2435100
color颜色名称（唯一键之一）Black
style_number从 URL 提取的产品 ID2435100
category从 URL 路径解析的分类tote bags
original_image_path相对于 repo 根目录的路径shopify/data/originals/...
status下载成功为 scraped，失败为 failedscraped
幂等性 以 (supplier_url, color) 为唯一键做 upsert，重复运行不产生副作用。

第二步A：OpenAI gpt-image-2 生成（标准路线）

适用：T恤 / 卫衣 / 杯子 / Tote 包所有类型

命令

python app/pipeline.py                  # 全量处理所有 status=scraped 的产品
python app/pipeline.py --force          # 强制重新生成（覆盖已有文件）
python app/pipeline.py --quality high   # 高质量模式（成本约 3x）
python app/pipeline.py --ids 113,114    # 只处理指定 product ID

Anchor 颜色选择策略

Pipeline 将同一 supplier_url 下所有颜色按组处理。每组只用 一种颜色（anchor）调用 OpenAI API，其余颜色通过 Python 色相旋转免费生成。

Anchor 选择优先级

优先级颜色原因
1051 Royal Blue色彩鲜明，与皮肤色调和牛仔裤色调分离度高
2040 Red已验证在 G64000L 上效果良好
3194 Cherry Red备选强饱和色
4098 Daisy（黄）备选暖色
…036 Black / 030 White无色相，仅在无其他颜色时才直接 API 生成
CustomInk 产品使用颜色名称匹配；凡 BLACK/WHITE/NATURAL/ASH/GREY 等非彩色均被排除在 anchor 候选外

三阶段执行

Phase 1 — gpt-image-2 API 调用（anchor + 无彩色备用）

调用 images.edit()，以 anchor 颜色的供应商参考图为输入，生成每个视角的产品图。

$0.063
每张 portrait 视图
1024×1536，medium quality
$0.042
每张 square 视图
1024×1024，medium quality
~$0.34
每个 anchor 颜色总成本
4 portrait + 2 square

Phase 2 — Python 色相旋转（免费）

对 anchor 的 6 张图做 HSV 色相旋转，批量生成所有其他颜色变体。通过 recolor.py 中的 numpy 向量化操作实现，无 API 费用。

限制 Anchor 必须是彩色（有色相）才能驱动 recolor。若产品只有黑/白/灰，每种颜色都需单独调用 API。

Phase 3 — 重建 review.html

调用 app/make_review_html.py，将 data/generated/ 下所有图片渲染为画廊 HTML，供人工审核。

第二步B：Codex CLI 生成（精品路线）

当前适用：Tote 包（Black / Natural 两色）

使用 Codex CLI 的 imagegen 工具生成超写实产品照，效果远优于 OpenAI 标准 path，适合旗舰产品首批上线。

命令

cd shopify/
python generate_bags_codex.py              # 生成全部（跳过已存在）
python generate_bags_codex.py --force      # 强制覆盖重新生成
python generate_bags_codex.py --dry-run    # 预览 prompts，不实际生成

Codex CLI 调用模式

# 核心命令构造
cmd = ["codex", "exec",
       "--ephemeral",
       "--skip-git-repo-check",
       "--sandbox", "read-only",
       "--color", "never"]

# 可选：传入参考图（--image 只支持一张）
if ref_img and Path(ref_img).exists():
    cmd += ["--image", ref_img]
cmd.append("-")   # 从 stdin 读取 prompt

# Prompt 格式（JSON 描述，通过 stdin 传入）
body = (
    "Use imagegen to create an image with this request:\n"
    + json.dumps(prompt, ensure_ascii=False)
    + "\n\nRequirements:\n"
      "- Generate the image directly\n"
      "- Do not provide explanation\n"
      "- Return only the image result"
)

# 执行（timeout=240s）
result = subprocess.run(cmd, input=body, capture_output=True, text=True, timeout=240)

输出收集逻辑

# Codex 把生成图写到 ~/.codex/generated_images/{session_ulid}/
CODEX_BASE = Path.home() / ".codex" / "generated_images"

# 1. 执行前快照现有目录
before = {d for d in CODEX_BASE.glob("*/") if d.is_dir()}

# 2. 执行 Codex CLI ...

# 3. 等待新目录出现（最多 30s 轮询）
while time.time() < deadline:
    after = {d for d in CODEX_BASE.glob("*/") if d.is_dir()}
    new = after - before
    if new:
        sess = sorted(new, key=lambda p: p.stat().st_ctime)[-1]
        imgs = list(sess.glob("*.png")) + list(sess.glob("*.jpg"))
        if imgs: break

# 4. 复制到 data/generated/，删除临时 session 目录
shutil.copy2(imgs[0], out_path)
shutil.rmtree(sess, ignore_errors=True)

Prompt 设计原则

字段要求
type明确摄影类型（e-commerce / editorial lifestyle / overhead flat lay / macro）
camera指定相机型号：Canon EOS R5，配焦距和光圈
quality必须包含 "REAL PHOTOGRAPH NOT AI mockup"
model（lifestyle 视角）白人女性，25–32 岁，白色圆领 T-shirt + 米色亚麻阔腿裤
lighting描述光源方向、阴影特征、是否有 bokeh
background明确说明（白色背景 / 城市街道 / 白色大理石等）
当前产品配置 000121 Black 参考图: customink_2435100_2435100_front.png
000130 Natural 参考图: customink_2435100_2435103_front.png

第三步：人工审核

打开生成的 review.html 进行可视化质量检查，对不满意的图片重新生成或用 --force 覆盖。

# pipeline.py 自动在 Phase 3 重建 review.html，也可手动触发：
python app/make_review_html.py && open review.html

# 或直接打开（若已存在）
open shopify/review.html
审核重点 检查：1) 颜色是否准确；2) 模特图是否出现真实人像；3) 产品细节是否清晰；4) 背景是否干净。

第四步：上传 Shopify CDN

将 data/generated/ 下的所有图片上传到 Shopify Files API，获取持久 CDN URL，写入 manifest 文件。

# 只上传新文件（manifest 中不存在的）
python app/upload_to_shopify.py

# 强制重新上传所有文件
python app/upload_to_shopify.py --force

# 指定并发数（默认 3，Shopify 有频率限制）
python app/upload_to_shopify.py --workers 2

两阶段上传协议（GraphQL Admin API）

Stage 1 — 申请预签名上传地址

mutation stagedUploadsCreate($input: [StagedUploadInput!]!) {
  stagedUploadsCreate(input: $input) {
    stagedTargets {
      url           # S3 presigned POST URL
      resourceUrl   # 上传后用于注册的资源 URL
      parameters { name value }
    }
  }
}

Stage 2 — PUT 文件到 S3 → 注册为 Shopify File → 轮询 READY

# POST 文件字节到 target.url（S3 presigned URL）
requests.post(target["url"], data=form, files={"file": ...})

# 注册为 Shopify File，获取 file_id
mutation fileCreate($files: [FileCreateInput!]!) { ... }

# 轮询 node(id: file_id) 直到 fileStatus == "READY"
for attempt in range(40):   # 最多等 ~80s
    time.sleep(1 if attempt < 5 else 2)
    node = graphql(FILE_NODE_QUERY, {"id": file_id})
    if node["fileStatus"] == "READY":
        return node["image"]["url"]  # cdn.shopify.com URL

{
  "000121_Black_bag_front.jpg":     "https://cdn.shopify.com/s/files/1/0746/6817/9644/files/000121_Black_bag_front.jpg?v=...",

  "000121_Black_bag_flat.jpg":      "https://cdn.shopify.com/s/files/1/0746/6817/9644/files/000121_Black_bag_flat.jpg?v=...",

幂等性 Manifest 中已有的 key 直接跳过，不重复上传。每上传 5 个文件做一次 checkpoint 写入 manifest，中断后可安全续传。

第五步：数据库入库

读取 manifest → 从 CDN URL 填充图片 → 通过 Prisma upsert 写入 PostgreSQL：Product + Variant + ProductImage + ProductCategory。

命令

# 开发环境（自动读 backend/.env 里的 DATABASE_URL）
node scripts/seed-tote-bags-online.js
node scripts/seed-mugs-online.js

# 生产环境（从 GCP Secret Manager 读取连接串）
DATABASE_URL=$(gcloud secrets versions access latest \
  --secret=database-url \
  --project=<PROJECT_ID>) \
  node scripts/seed-tote-bags-online.js

Seed 脚本模式（以 seed-tote-bags-online.js 为参考）

// 1. 读 manifest
const manifest = JSON.parse(fs.readFileSync(MANIFEST_PATH, 'utf8'));

// 2. 构建 CDN URL（key 格式必须和 pipeline.py 输出一致）
function cdnUrl(manifest, productId, colorSlug, view) {
  const key = `${productId}_${colorSlug}_${view}.jpg`;
  const url = manifest[key];
  if (!url) throw new Error(`Manifest missing key: ${key}`);
  return url;
}

// 3. 对每个颜色：先删旧记录（refresh 模式）再创建
const existing = await prisma.product.findUnique({ where: { slug: productSlug } });
if (existing) {
  await prisma.productImage.deleteMany({ where: { productId: existing.id } });
  await prisma.variant.deleteMany({     where: { productId: existing.id } });
  await prisma.productCategory.deleteMany({ where: { productId: existing.id } });
  await prisma.product.delete({ where: { id: existing.id } });
}

// 4. 创建 Product with nested variants + images + category
await prisma.product.create({
  data: {
    name, slug, basePrice: 1999,  // 单位：分
    sku, stockQuantity: 300, isActive: true,
    variants:          { create: [variant] },
    images:            { create: productImages },
    productCategories: { create: { categoryId: bagsCategory.id } },
  }
});

新增产品类型 Checklist

只需改 2 个文件，scraper / pipeline / upload 脚本无需改动（它们消费 build_prompts() 的输出）：

  • app/prompts.py — 新增 4 处：
    1. VIEWS_NEWTYPE 列表（每项含 key / label / summary / needs_model / directive / aspect）
    2. is_newtype_product(product) 函数 — 检查 _full_text(product) 是否含关键词
    3. 在 build_prompts() 和 build_prompt() 中路由到新类型
    4. 在 guess_garment() 中返回产品标签文字
    5. 把 VIEWS_NEWTYPE 追加到 ALL_VIEWS
  • app/generate.py — 在 VIEW_SIZE 字典中添加新 view key 的尺寸：
    portrait 模特视角 → "1024x1536"；平铺/特写视角 → "1024x1024"
  • scripts/seed-{newtype}-online.js — 参照 seed-tote-bags-online.js 创建入库脚本
规则 标准服装类（T恤/卫衣/Polo/外套/帽子）无需改代码。URL slug 自动成为 product_name，guess_garment() 自动解析，走 VIEWS 默认路由。
